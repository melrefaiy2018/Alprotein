Alprotein Scientific Workbench — UI/UX Proposal v3

This is a static visual proposal — no code changes have been made yet. It targets the live workbench (Alprotein/gui/workbench_app.py + workbench_window.py) and addresses the gaps called out for this branch: project save/load (.alproj), recent files, undo, progress cancellation, dark mode, in-app docs/tooltips with references, error toasts, pigment ↔ Hamiltonian ↔ spectrum cross-highlighting, and a pyqtgraph-backed spectrum widget with live sliders. The current protein_viewer.py already uses py3Dmol + QWebEngineView, so the 3D upgrade is interaction (selection, highlighting) rather than swapping the backend.

4. Cross-cutting Patterns

Project model (.alproj) NEW

Zipped HDF5 bundle: PDB + parameter dict + computed Hamiltonian + spectra + notebook text + view state. Recent files list in ~/.alprotein/recent.json. Auto-save every 60s into ~/.alprotein/autosave/. Drag a .alproj onto the drop zone to restore the entire session including selection and camera.

Undo / Redo NEW

Command-stack on parameter edits, site-energy overrides, domain-cutoff changes, selection toggles. QUndoStack with a visible "history" panel (Window menu → History). Calculations themselves are not undone — only the inputs that produced them.

Progress & cancellation CHANGED

Replace the silent QThread + dead-end progress label with a real progress bar in the status bar that has a Cancel button and ETA. Worker checks a stop flag inside the ensemble loop. Successful runs flash a green check; failures raise an error toast (top-right) with a "Copy traceback" button instead of dumping into the status label.

In-app docs & citations NEW

Every parameter has a tooltip with units, typical range, and a DOI. Help → "What is…?" opens a side panel rendering the markdown reference (CDC / TrEsp / Renger lineshape / disorder). Bundled, no internet required.

Command palette ⌘K NEW

Type to find any action ("export hamiltonian", "set σ=200", "open last project"). Pulls actions from the menu bar and named commands. Big productivity win for power users.

Theme system NEW

Centralize the inline stylesheets currently scattered across workbench_app.py, tools_panel.py, protein_viewer.py into a single QSS token file with Light and Dark variants. py3Dmol scene gets a matching dark background.

Error toasts NEW

Non-blocking notifications anchored bottom-right with severity color, auto-dismiss after 6s, click to expand. Replaces the current habit of QMessageBox.warning for non-blocking conditions and silent failures via the status label.

5. What This Replaces / Removes

  • REMOVE Legacy GUI stacks: gui/app.py, gui/app_pro.py, gui/main_window.py, gui/main_window_pro.py, and widgets only they reference.
  • CHANGED gui/__init__.launch_gui redirects to workbench_app.main; add console-script alprotein.
  • CHANGED Split workbench_window.py (1796 LOC) into a thin assembler + controllers/{calculation, results, export, selection}_controller.py.
  • CHANGED Spectrum widget moves to pyqtgraph for interactive view; matplotlib is kept only for the "Export figure" code path.
  • NEW Project model (.alproj) · Recent files · Undo · Command palette · Theme · Toasts · Inspector · Cross-highlighting · Domains panel · Fit-to-experiment tab.
  • KEEP py3Dmol + QWebEngineView 3D viewer (only add selection/highlight wiring and an exciton-scrub bar).

6. Phased Implementation (after your approval)

  1. Phase A — Plumbing (1–2 days): consolidate GUI entry points; QSS theme tokens (light/dark); status bar with cancel; toast widget; tooltip+citation registry; command palette skeleton.
  2. Phase B — Project & History (2–3 days): .alproj save/load + recent files + auto-save; QUndoStack wiring for parameter edits and overrides.
  3. Phase C — Cross-Highlighting (2–3 days): single SelectionModel consumed by 3D viewer, Hamiltonian widget, spectrum widget, inspector; py3Dmol JS bridge for click events; exciton scrub bar.
  4. Phase D — pyqtgraph spectrum (2–3 days): port live sliders; keep matplotlib path for publication export; add experiment overlay + RMSE; CD/LD checkboxes (rendering stubbed pending calc).
  5. Phase E — Fit-to-Experiment tab (3–5 days): least-squares fitter UI with locked/free site energies, live RMSE, fit history.
